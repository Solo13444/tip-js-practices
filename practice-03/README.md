## 2. Задание 1. Исследование DOM и событий

На странице `examples/dom-events.html` доступны пять экспериментов. Их результаты можно проверить в DevTools → Console.

| № | Эксперимент | Ожидаемое наблюдение | Объяснение |
|---|---|---|---|
| 1 | Отсутствующий элемент и пустая коллекция | `querySelector` возвращает `null`; `querySelectorAll` возвращает коллекцию длины `0`. | Это разные типы результата: одиночный элемент или коллекция. |
| 2 | `dataset.taskId` до и после преобразования | Значение из `dataset` имеет тип `string`; `Number(...)` возвращает число. | Значения `data-*` читаются как строки. |
| 3 | Добавить запись дважды | Сохранённый `initialItems` остаётся коллекцией исходной длины, новый `querySelectorAll` показывает увеличенное количество. | `querySelectorAll` возвращает статический `NodeList`, не обновляющийся после добавления элементов. |
| 4 | Вывести строку с тегом `<strong>` через `textContent` | В заголовке отображаются угловые скобки и текст; настоящий элемент `strong` не создаётся. | `textContent` выводит текст безопасно, не разбирая строку как HTML. |
| 5 | Нажатие по вложенному `span` кнопки | В консоли видны сообщения обработчика кнопки и всплытия; `target` — элемент, по которому нажали, `currentTarget` — элемент текущего обработчика. | Событие `click` всплывает по DOM-дереву; поэтому делегированный обработчик ищет кнопку через `closest`. |

## 3. Задание 2. Карточка задачи и список

В `src/task-view.js` реализованы функции `createTaskElement` и `renderTaskList`. Карточка — элемент `li.task-card` с атрибутом `data-task-id`; у завершённой записи добавляется `is-completed`. Название, статус и приоритет выводятся отдельными элементами. Кнопки статуса и удаления — настоящие элементы `button`, имеют `type="button"`, `data-action` и вложенный `span.action-label`.

Название задачи выводится через `textContent`, поэтому текст пользователя вроде `<strong>Проверка</strong>` не интерпретируется как HTML. При повторном отображении `renderTaskList` использует `replaceChildren`, карточки не дублируются, а контейнер списка остаётся тем же.

## 4. Задание 3. Делегирование событий и действия

Обработчик кликов назначается контейнеру `#task-list` один раз. Через `event.target.closest("button[data-action]")` определяется действие, а через `closest("li[data-task-id]")` — карточка. Идентификатор преобразуется в число и дополнительно проверяется как положительное безопасное целое.

Переключение статуса выполняется через `setTaskCompleted` из ПР2, удаление — через `removeTask`. Интерфейс не удаляет карточку напрямую и не меняет только CSS-класс: после успешной сервисной операции сохраняется новый массив и выполняется повторная отрисовка. При отказе выводится сообщение, прежнее состояние остаётся неизменным. После перерисовки фокус возвращается на соответствующую кнопку, а если карточка исчезла из текущего фильтра — на кнопку фильтра.

## 5. Задание 4. Фильтры, сводка и пустое состояние

Функция `getVisibleTasks` поддерживает три режима: `all`, `pending` и `completed`. Фильтрация не изменяет основной массив и сохраняет порядок задач. После выбора фильтра или успешного изменения обновляются карточки, сводка и количество видимых записей.

Сводка вычисляется по всему текущему массиву, а не только по видимым карточкам. Поэтому фильтр «В работе» не обнуляет общий прогресс. Для пустого списка отображается `Список задач пуст.`, а при отсутствии совпадений фильтра — `Нет задач по выбранному фильтру.`. При ненулевой видимой выборке сообщение скрывается.
