## 2. Задание 1. Функции, ссылки и копирование

| Эксперимент | Результат | Объяснение |
|---|---|---|
| `sum(2, 3)` и `sum("2", 3)` | `5` типа `number`; `"23"` типа `string` | Функция не преобразует типы автоматически. Оператор `+` зависит от типов операндов. |
| Стрелочная функция `square` с телом в фигурных скобках | Исходный вариант без `return` возвращал `undefined`; исправленная `square(4)` возвращает `16` | Результат выражения внутри блока не возвращается автоматически. |
| Присваивание объекта другой переменной | После `sameUser.name = "Мария"` изменяется объект, видимый через `originalUser`; сравнение ссылок возвращает `true` | Обе переменные ссылаются на один объект. |
| Копия массива через spread | Длина исходного массива остаётся `2`, длина копии — `3`; изменение вложенного объекта видно в исходном массиве | Spread массива выполняет поверхностное копирование: сам массив новый, вложенные объекты остаются общими. |
| Spread объекта и повторное свойство | Новый объект содержит новое название, исходный объект остаётся без изменения | Поле, указанное после spread, переопределяет прежнее; верхнеуровневый объект копируется. |
| Параметр по умолчанию | Без аргумента и с `undefined` результат `medium`; `null` и `""` сохраняются как переданные значения | Значение по умолчанию применяется к пропущенному аргументу или `undefined`, но не к `null` или пустой строке. |

Второй эксперимент исправлен: `square(4)` возвращает `16`. В исходном варианте пропущен `return`, поэтому функция возвращала `undefined`.

## 3. Задания 2–4. Модель и функции сервиса

В `task-service.js` реализованы девять функций: `createTask`, `findTaskById`, `getPendingTasks`, `getTaskTitles`, `getTaskStats`, `addTask`, `setTaskCompleted`, `renameTask` и `removeTask`.

Создание задачи проверяет идентификатор на положительное безопасное целое число, название — на строковый тип и длину от 1 до 100 символов после `trim()`, а приоритет — на значения `low`, `medium` или `high`. Новая задача получает `completed: false` и приоритет `medium` по умолчанию.

Для изменения данных используется неизменяющий подход: добавление создаёт массив через spread, изменение статуса или названия — новый массив через `map` и новый объект изменённой задачи, удаление — новый массив через `filter`. При отказе возвращается `{ ok: false, error }`; исходный массив не меняется.

Общий демонстрационный набор имеет сводку `{ total: 4, completed: 2, pending: 2, progress: 50 }`. Поиск использует `find`, отбор незавершённых задач — `filter`, получение названий — `map`. Для пустого списка все показатели сводки равны нулю.

## 4. Индивидуальный вариант 4

Тема варианта — **подготовка семинара**. Идентификаторы исходных задач: `[11, 23, 37, 41, 58, 64]`. Первые три задачи отмечены выполненными. В наборе присутствуют все три приоритета. Новая задача `id = 80` добавляется с приоритетом `high`.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 0 | Исходный набор варианта | 6 задач, 3 выполнены, 3 осталось, прогресс 50.0%. |
| 1 | Добавить `id = 80` «Подготовить раздаточные материалы» | 7 задач, 3 выполнены, прогресс около 42.9%. |
| 2 | Установить статус `id = 11` в `true` | Успех; массив остаётся корректным, статус уже был `true`. |
| 3 | Переименовать `id = 23` | Название обновлено; остальные поля не изменены. |
| 4 | Удалить `id = 37` | Задача удалена; остальные ID сохраняются в исходном порядке. |
| 5 | Повторно добавить `id = 80` | Отказ с понятным сообщением; состояние остаётся без изменений. |

После сценария остаются ID `[11, 23, 41, 58, 64, 80]`. Исходный экспортированный `variantTasks` остаётся без изменений.

## 5. Проверки

Команда `npm run check` запускает автоматизированные проверки основных контрактов: валидные и ошибочные значения, границы названия и идентификатора, чтение списков, расчёт сводки, добавление, изменение статуса, переименование, удаление и отсутствие мутаций исходного набора. Итоговое количество пройденных проверок выводится в консоль.

Контракты сервиса отделены от демонстрационного сценария, а операции изменения не мутируют входные данные.
